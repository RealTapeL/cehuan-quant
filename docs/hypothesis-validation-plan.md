# 停牌窗口与零股目标研究假设验证计划

**用途：** 将短窗口审计观察变成可证伪的研究问题。此文不修改冻结策略、不运行新策略、不生成个人交易建议或券商委托。

## 研究边界

- 已审计的 2024-10-08 至 2025-01-10 短窗口已被用于发现数据与实现问题，只能作为开发诊断，不能称为独立留出样本。
- 正式基线保持 `NOT_READY`，增量续跑保持 `can_continue=false`。策略规则、历史交易单位、市场规则、费率和公告时点仍有未核实项。
- 每条假设先在已知开发窗口验证程序定义和输出，再冻结代码、数据、配置、指标和门槛。独立区间必须在冻结后选取，不能根据收益挑选。
- 只有在该假设所需的点时状态、交易规则、费用、公司行动和行情时点证据齐备后，才解释收益类指标；否则只报告信号、目标、状态覆盖和阻断情况。

## H1：动量窗口中停牌与未知状态的处理

**观察：** 某候选在其 20 日回看窗口中包含停牌行情，且在信号日排名靠前。该事实本身不证明信号计算错误或策略表现较差。

**待检验问题：** 在相同股票池、20 日动量、排名、调仓节奏和执行规则下，若买入候选要求整个 21 行观察窗口的停牌状态均已知且均为非停牌，候选集、排名和后续交易诊断会怎样变化？

| 要素 | 冻结定义 |
|---|---|
| 对照组 | 当前策略：在信号日按现有状态规则筛选，特征按每只股票的行情行 `shift(20)` 计算。 |
| 候选组 | 仅作研究比较：买入候选的 21 个连续开市日窗口必须与 21 条唯一行情逐日对应，且停牌状态全部已知为非停牌；否则不进入新买候选。 |
| 固定项 | 股票池快照、动量价格口径、`lookback_sessions=20`、排名排序、最大持仓、调仓频率、交易费用与订单规则输入。 |
| 主要诊断指标 | 候选数、停牌/未知状态候选数、排名变动、目标变动、未能形成有效数量的目标、模拟成交记录、明确的模拟阻断尝试。 |
| 收益指标 | 仅在相同且已核实的输入和执行假设下作辅助指标；需同时报告回撤、换手、费用和受阻交易。 |
| 失败/停止条件 | 窗口与日历不一致、重复证券日、停牌状态未知、历史行情供应商版本或决策可得时点未知时，不得把结果提升为策略证据。 |

候选组是明确的研究变体，不是当前建议。必须保存被过滤的证券、日期和原因；不得把缺失行情静默解释为停牌或非停牌。

覆盖审计分别统计每个信号日的 `STOCK_MEMBER` 全股票池和原始候选池。“H1 完整窗口”只表示日历、行情行和行内停牌字段满足程序规则。若证券状态历史来源、逐字段可得时点或行情版本未核实，仍不能把窗口称为已通过点时验证。

## H2：目标股数舍入为零后的现金处理

**观察：** 一只已按排名选中的候选，其目标金额除以执行参考价后不足配置的最小交易单位，舍入后目标股数为零；研究账本保留现金。现有实现先取排名前 `max_positions` 个候选，再逐只按交易单位舍入。

**待检验问题：** 在冻结的仓位上限、总风险预算、交易单位和费用条件下，原候选舍入为零后继续搜索下一名可买候选，是否比保留现金产生可接受的风险、换手和组合暴露变化？

| 要素 | 冻结定义 |
|---|---|
| 对照组 | 当前顺序：先选排名前 N 名，再按交易单位向下取整；零股目标保留现金，不自动补位。 |
| 候选组 | 研究变体：若目标向下取整为零，按排名继续检查后续候选，直到获得 N 个有效数量目标或候选耗尽；原总仓位、单股权重、交易规则与费用不变。 |
| 固定项 | 同一信号日、同一排名、同一参考价可得时间、同一账户初始状态、同一交易规则/费用版本。 |
| 主要诊断指标 | 零目标数、被替补目标数、实际目标数、留存现金比例、组合暴露、换手、费用、未成交/受阻模拟尝试。 |
| 收益指标 | 仅作为预先注册实验的次要指标；必须与风险和交易成本一起报告。 |
| 失败/停止条件 | 交易单位来源是未核实回退值、执行参考价时点不明确、候选池/市场规则不完整或手续费未核实时，状态为 `NEEDS_DATA`。 |

该变体不得改变当前有效策略配置。不能根据已看过的短窗口选择保留现金或补位方案。

### H2 合成原型的冻结时间线

当前原型选择**观察后延迟一个交易日执行**这一种清晰可检验的定义：

1. 信号日收盘后形成排名，记录 `ranking_available_at_utc` 和输入来源。排名必须早于补位决策；存在排名文件不代表已证明历史时点当时可得。
2. 使用规范化交易日历验证信号日、决策日和执行日是连续三个开市日。决策日和执行日分别记录 `decision_at_utc`、`execution_at_utc`。
3. 决策报价与证券状态分别记录 `price_available_at_utc` / `price_source` 和 `status_available_at_utc` / `status_source`。报价及状态都必须在决策前可得，不能用一个行情时间戳代替状态来源与时点。
4. 下一开市日开盘信息可得后，检查前 N 个目标中是否有目标股数为零；本原型只为新买空槽补位，已有持仓的零目标再平衡退出暂不包含。按排名选择可形成正数量的首个候选，冻结代码和股数。
5. 最早在再下一开市日模拟执行。执行报价也分别记录价格与状态来源、可得时间。该价格只验证冻结数量是否仍满足预算、费用和可交易条件；不能据此另选股票或改变数量。

因此候补**不会**在观察主目标开盘价的同一开盘价成交。合成执行也不证明真实开盘可成交；涨跌停队列、滑点、流动性和历史规则仍是数据门槛。

原型的订单状态为 `SCHEDULED_SIMULATED_ORDER`；结果状态为 `SIMULATED_FILL_UNDER_OPEN_PRICE_ASSUMPTION`。后者表示程序按执行日开盘价假设计算了模拟成交，不代表真实订单可按该价格成交，也不是市场成交证据。报价、状态、规则或价格时点不符合输入契约时，应阻断或标为未知。

整套 H2 候选方案相对原策略同时改变了候补选择和执行延迟；两组差异不能只归因于补位。另设相同决策/执行时间线的 matched-horizon 对照：控制组把零目标现金留到相同期限，候选组持有冻结的替补订单。未核实规则、费用和时点时，只比较程序行为及阻断，不解释策略收益。

## 实验登记与复现

每次运行保存：研究假设 JSON、原始和规范输入哈希、代码提交、策略配置哈希、行情与交易日历范围、历史规则与费用版本、公司行动覆盖状态、指标定义、候选组差异和运行时间。研究假设使用现有 Agent schema；`human_review_required=true`、`may_modify_active_strategy=false`、`may_generate_orders=false` 必须保持。

正式结果门槛至少要求：

1. 研究窗口与交易日历逐证券对齐，重复/缺失/窗口外数据有明确报告；
2. 停牌、上市、ST 与退市状态采用按历史日期的数据，未知状态不得静默填为否；
3. 数据的可得时点、来源版本、公司行动、历史市场规则及费用口径满足本实验要求；
4. 对照组和候选组使用相同输入与执行约束，唯一差异为预先登记的候选规则；
5. 开发窗口不作为独立留出，另选冻结后的时间区间或开展前瞻纸面跟踪；
6. 任何候选改动均由用户审核后另建策略版本，研究流程不连接券商。

每次 H1/H2 运行的登记还应保存：假设 ID 和版本、控制/候选规则差异、策略配置和代码哈希、输入文件与输出文件哈希、信号/排名/决策/执行时间、交易日历、股票池、规则、费率、公司行动状态、初始现金与持仓、指标定义、停止条件及人工审核状态。数据相同且只改变已登记的一条规则；缺少门槛时只报告程序行为与阻断，不给收益优劣结论。

## 合成原型复现

可用纯合成行情运行 H1/H2 程序行为验证，并在新的私有目录保存实验登记、输入、控制/候选差异和结果：

```bash
uv run python scripts/run_hypothesis_prototypes.py \
  --output-dir data/private/experiments/hypothesis-prototypes-synthetic-<unique-id>
```

脚本拒绝覆盖已有目录。结果类型固定为 `SYNTHETIC_PROGRAM_BEHAVIOR_DIAGNOSTIC_NOT_STRATEGY_BACKTEST`；不会读取真实账户、改变当前策略或产生券商委托。每次运行的 `experiment-manifest.json` 固定代码提交/工作区、代码与合成输入哈希、假设和时间边界、控制/候选差异、预算及停止条件；它不证明真实数据有效性。

## 私有真实输入覆盖预检

本地只读预检入口为 `scripts/audit_hypothesis_input_coverage.py`。它复用项目规范行情和交易日历适配器，分别检查 H1 全股票池、H1 原候选的 21 开市日窗口，以及 H2 候选在下一两个开市日的报价、证券状态和交易规则字段。文件清单哈希、当前文件哈希、原运行时锚点、字段是否存在、历史可得时点证据会分开记录。

```bash
uv run python scripts/audit_hypothesis_input_coverage.py \
  --output-dir data/private/experiments/hypothesis-input-coverage-<unique-id>
```

脚本只读输入，在运行前后比对源文件哈希，并拒绝覆盖已有结果目录。逐证券 CSV、JSON 和摘要 Markdown 都留在 `data/private/`，不计算策略收益、不运行交易策略，也不产生交易计划。此 68 开市日开发窗口不能作为独立留出；本轮发现的数据缺口与实验登记口径见 [`hypothesis-data-gaps.md`](hypothesis-data-gaps.md) 和 [`hypothesis-experiment-registration.md`](hypothesis-experiment-registration.md)。

## 登记日权益证据范围

这轮仅将证据范围整理到 [`evidence/record-date-entitlement-evidence.csv`](evidence/record-date-entitlement-evidence.csv)。它按来源、市场范围和能否明确回答登记日当日交易来记录证据边界；不更改现有账本政策，也不确认任何个人账户实际权益。来源文件链接或哈希本身不能代替适用性审查与账户结算记录。
